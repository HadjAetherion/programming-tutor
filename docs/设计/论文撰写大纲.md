## 摘要草稿（可直接修改使用）

### 中文摘要

> 在线判题系统能够判定代码正确性，却难以回答"错在哪里、为什么错、下一步学什么"等教学性问题。将大语言模型引入编程辅导虽可提升反馈质量，但云端推理成本高、免费额度限流严重，且缺乏对学生知识状态的建模，导致反馈缺乏个性化。
>
> 本文设计并实现了一套面向在线编程学习的多智能体协同诊断与自适应辅导系统。系统在判题链路之后引入四个职责分离的智能体——诊断、反馈、审查与规划，采用两阶段并行编排：诊断与审查并行执行，反馈与规划分别消费上游结果，通过显式上下文协议传递中间状态。为在质量与成本间取得平衡，系统设计了基于规则的轻量级路由决策器，依据教学任务异质性（错误类型、代码复杂度、干预策略）动态选择端侧小模型（Qwen2.5-7B）或云端大模型（GLM-4.7-Flash），并在端侧故障时自动回退。系统还构建了覆盖 Go、Python、Java、C++ 四种语言的知识图谱，采用指数移动平均（EMA）增量更新学生掌握度，使学习规划由"通用建议"转为"基于学情的针对性建议"。实验部分采用准实验设计，以强制全云端架构为对照组，从学习效果、认知负荷、推理成本与响应延迟四个维度进行评价。
>
> 实验结果表明：……（待实验完成后填写）。系统已实现多语言判题、四智能体协同诊断、学情驱动的学习规划与成本可视化仪表盘，为编程教育中的智能辅导提供了一种兼顾质量与成本的工程方案。

**关键词**：多智能体系统；大语言模型；编程教育；自适应辅导；模型路由；知识追踪

### English Abstract

> Online judges can determine whether code is correct, but they cannot answer pedagogical questions such as where the error lies, why it occurred, and what to learn next. Introducing large language models (LLMs) into programming tutoring improves feedback quality, yet cloud inference is costly, free quotas are heavily rate-limited, and the absence of student knowledge modeling makes feedback generic.
>
> This thesis designs and implements a multi-agent collaborative diagnosis and adaptive tutoring system for online programming learning. Four role-separated agents—diagnosis, feedback, review, and planning—are orchestrated in two parallel stages: diagnosis and review execute concurrently, while feedback and planning consume upstream results through an explicit context protocol. To balance quality and cost, a lightweight rule-based router selects between an on-device small model (Qwen2.5-7B) and a cloud LLM (GLM-4.7-Flash) according to the heterogeneity of pedagogical tasks, with automatic fallback on device failure. A knowledge graph covering Go, Python, Java, and C++ supports an exponential moving average (EMA) mastery model, enabling student-specific study planning. A quasi-experimental design evaluates the system against an all-cloud baseline on learning gains, cognitive load, inference cost, and latency.
>
> （Results pending.）The system implements multi-language judging, four-agent collaborative diagnosis, mastery-driven planning, and a cost-aware dashboard, offering an engineering solution that balances quality and cost for intelligent tutoring in programming education.
>
> **Keywords**: multi-agent system; large language model; programming education; adaptive tutoring; model routing; knowledge tracing

## 写作注意事项

1. **创新点要"回应式"写作**：第 1 章提出三个创新点，第 4 章设计对应，第 5 章实现对应，第 6 章评估对应，第 7 章总结逐条回应。
2. **避免只描述"用了什么技术"**，要写"为什么这样选、备选是什么、代价是什么"——概要设计第 7 节的权衡表可直接改写成论述段落。
3. **实验章要诚实**：样本量小就说明小，用效应量补充；免费额度导致成本为 0 就解释清楚并用 Token 作为代理指标。
4. **截图要脱敏**：不要出现真实邮箱、API Key、数据库密码。
5. **查重**：设计文档与论文表述需重写，不可整段复制。
