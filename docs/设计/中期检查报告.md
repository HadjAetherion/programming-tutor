## 一、选题背景与研究目标

在线判题系统（OJ）解决了"代码对不对"的问题，却没有解决"为什么错、怎么改、下一步学什么"。直接引入大语言模型做辅导，又面临两个现实约束：云端模型调用成本高、免费额度限流严重（实测并发 2 个请求即被拒，响应可达数十秒），而且模型不了解学生历史薄弱点，建议缺乏个性化。

本课题的目标是构建一套**多智能体协同诊断与自适应辅导系统**，在判题之后自动完成教学性反馈，并通过**大小模型协同路由**在质量、成本与延迟之间取得平衡。三个创新点为：

1. 面向教学任务异质性的推理路由
2. 多智能体中嵌入成本感知调度
3. 成本—质量联合评估

### 2.2 已实现的核心功能

1. **四智能体协同诊断**：诊断、审查并行执行；反馈消费诊断结果、规划消费诊断+审查+学情，两阶段并行编排。单个 Agent 失败不影响其余 Agent。
2. **自适应干预策略**：按判题状态与通过率规则式选择"直接提示 / 苏格拉底式提问 / 分步引导"，规则可解释。
3. **大小模型协同路由**：按 Agent 角色、错误类型、代码长度、干预策略动态选择端侧 Qwen2.5-7B 或云端 GLM-4.7-Flash；端侧失败自动回退云端；支持强制全云端开关作为对照。
4. **知识图谱与学情模型**：Go/Python/Java/C++ 四语言各自的概念图谱（共 88 节点），诊断命中自动标注题目、更新 EMA 掌握度；规划 Agent 读取薄弱知识点。
5. **多语言判题沙箱**：Docker 隔离，支持 Go / Python / Java / C++ 四种语言。
6. **学习仪表盘**：掌握度排名图、按角色的端云延迟对比、调用成本明细。
7. **实验支撑**：26 道题、90 个测试用例、前后测平行卷、NASA-TLX 问卷、统计脚本（Mann-Whitney U + Cliff's δ + 成本质量联合评估表）。
