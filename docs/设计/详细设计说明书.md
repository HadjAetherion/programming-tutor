### 1.2 表结构

#### 1.2.1 submissions（提交）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | 提交 ID |
| user_id | BIGINT | 提交者 |
| problem_id | BIGINT | 题目 |
| language | VARCHAR | 规范语言标识：go/python/java/cpp |
| code | TEXT | 源代码 |
| status | VARCHAR | ACCEPTED / WRONG_ANSWER / COMPILE_ERROR / RUNTIME_ERROR / TIME_LIMIT |
| stdout / stderr | TEXT | 最后执行的输出 |
| exit_code | INT | 退出码 |
| execution_time_ms | BIGINT | 累计执行耗时 |
| passed_tests / total_tests | INT | 通过用例数 / 总用例数 |

**设计说明**：`language` 存**归一化后的值**（`c++`→`cpp`、`py`→`python`），避免同一语言出现多种写法导致统计分裂。

#### 1.2.2 submission_diagnosis（诊断结果）

| 字段 | 类型 | 说明 |
|---|---|---|
| submission_id | BIGINT | 关联提交 |
| user_id | BIGINT | 冗余，便于按用户查询 |
| error_type | VARCHAR | 诊断 Agent 的错误类型 |
| root_cause | TEXT | 根因 |
| concepts | JSONB | 命中知识点数组 |
| explanation / hint | TEXT | 讲解与提示 |
| feedback | JSONB | 反馈 Agent 完整产出 |
| review | JSONB | 审查 Agent 完整产出 |
| planning | JSONB | 规划 Agent 完整产出 |
| model_name / model_tier | VARCHAR | 聚合模型与层级（mixed 表示混合） |
| latency_ms | BIGINT | 全流程墙钟时间 |
| prompt_tokens / completion_tokens | INT | 四次调用合计 |
| cost_yuan | DOUBLE | 四次调用合计成本 |

**设计说明**：四个 Agent 产出结构异构且可能演进，用 JSONB 避免频繁改表；`concepts` 单独抽出为列便于按知识点聚合。

#### 1.2.3 llm_call_log（调用日志）

单次调用一行：`agent_role`、`model_tier`、`model_name`、`latency_ms`、`prompt_tokens`、`completion_tokens`、`cost_yuan`、`user_id`、`submission_id`。

**这是创新点③的数据基础**：仪表盘与统计脚本的成本/延迟对比全部由此表聚合。

#### 1.2.4 知识图谱四表

| 表 | 主键 | 说明 |
|---|---|---|
| knowledge_nodes | (language, name) | 概念节点，含 category/description |
| knowledge_edges | (language, from_node, to_node) | 先修关系，复合外键至 nodes |
| problem_concepts | (problem_id, language, concept_name) | 题目标注，含 hit_count |
| student_mastery | (user_id, language, concept_name) | 掌握度、尝试数、薄弱次数 |

**设计说明**：复合主键是**多语言支持的关键**。Go 与 Python 都有"循环"，若以 `name` 单列为主键会导致后插入者被忽略（该缺陷在实现过程中真实出现过，由 007 修正）。

#### 1.2.5 实验数据三表

| 表 | 主键 | 说明 |
|---|---|---|
| experiment_groups | user_id | group_name ∈ {experimental, control} |
| assessment_scores | (user_id, phase) | 前测/后测，score + max_score |
| nasa_tlx | user_id | 六维度评分 + 加权总分 |

## 2. 后端详细设计

### 2.1 分层与依赖方向

```
handler ──► service ──► repository ──► DBTX ──► pgxpool
   │            │
   │            └──► sandbox（判题）
   │            └──► diagnosis.Client（HTTP 调 Agent 服务）
   └──► middleware（JWT 注入 user_id）
```

**约束**：handler 不直接写 SQL；repository 不含业务规则；sandbox 不感知业务模型。

### 2.2 判题流程（JudgeService.Judge）

```go
func (s *JudgeService) Judge(ctx, problemID, code, language) (*JudgeResult, error)
```

1. 读取该题全部测试用例
2. 调用 `runner.Compile(ctx, code, language)` → 得到工作目录与编译结果
3. 编译失败 → 返回 `COMPILE_ERROR` + stderr
4. 逐用例 `runner.Run(ctx, workDir, input, language)`
5. 超时 → `TIME_LIMIT`；非零退出 → `RUNTIME_ERROR`；输出不匹配 → `WRONG_ANSWER`
6. 全部通过 → `ACCEPTED`
7. `defer cleanup()` 清理临时目录

### 2.3 沙箱实现（sandbox 包）

**核心抽象**：

```go
type Spec struct {
    Language    string
    Image       string
    SourceFile  string
    CompileArgs []string   // 空表示解释型
    CompileOut  string
    RunArgs     []string
}
```

**Docker 调用参数**：

```go
docker run --rm \
  --mount type=bind,source=<tempDir>,target=/workspace \
  --workdir /workspace <image> <command...>
```

运行阶段统一以 `sh -c "<cmd> < input.txt"` 注入标准输入。

**解释型语言的处理**：Python 无编译阶段，但需要在编译阶段捕获语法错误。实现为：

```go
if len(spec.CompileArgs) > 0 {
    // 编译型：执行编译命令
} else {
    // 解释型：python -m py_compile main.py
}
```

这样 Python 的 `SyntaxError` 会被归入 `COMPILE_ERROR`，与用户体验一致。

### 2.4 诊断调用

**请求构造**（`DiagnosisService.DiagnoseSubmission`）：

- 提交信息：id、user_id、problem_id、code、language
- 题目信息：标题、描述、输入/输出说明、约束、样例
- 判题信息：状态、stdout/stderr、退出码、通过/总用例数

**响应落库**：四个 Agent 产出分别序列化为 JSONB，调用元信息写入列。

**超时**：HTTP 客户端与前端 axios 均设为 300s（云端限流下全流程可达 2~4 分钟）。

### 2.5 学情上报（异步）

判题结果为 `ACCEPTED` 时：

```go
go func() {
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    client.RecordMastery(ctx, userID, problemID, language)
}()
```

**设计说明**：fire-and-forget，失败仅记日志。掌握度是辅助数据，不应拖慢或阻断判题响应。

### 2.6 查询接口

| 接口 | SQL 要点 |
|---|---|
| `GET /me/mastery` | `student_mastery` 按 `language, mastery ASC` 排序；可选按语言过滤 |
| `GET /me/llm-stats` | `llm_call_log` 按 `(agent_role, model_tier)` 分组，AVG 延迟/Token，SUM 成本 |
| `GET /submissions` | `submissions LEFT JOIN submission_diagnosis` 得出 `has_diagnosis` |

## 3. Agent 服务详细设计

### 3.1 请求处理链路

```
POST /api/v1/diagnose
  └─ routers/diagnose.py   校验 ZHIPU_API_KEY，构造 AgentContext
      └─ orchestrator.diagnose(ctx)
          ├─ 阶段一：gather(_run_agent(DiagnosisAgent), _run_agent(ReviewAgent))
          ├─ knowledge.on_diagnosis(...)          ← 学情更新（失败不影响主流程）
          ├─ 阶段二：gather(_run_agent(FeedbackAgent), _run_agent(PlanningAgent))
          └─ 聚合 meta（模型集合、tier、总延迟、Token、成本）
```

### 3.2 Agent 基类契约

```python
class Agent:
    name: str
    async def run(self, ctx: AgentContext, gateway: ModelGateway) -> Tuple[Output, LLMResponse]
```

每个 Agent 自行负责：消息构建（`build_messages`）→ 调用网关 → 解析 LLM 输出（容错）。

**JSON 解析容错**：`_extract_json` 依次处理 ```json 包裹、前后多余文字、截断；解析失败时退化为纯文本摘要，不抛异常。

### 3.3 模型网关

```python
async def complete(messages, *, agent_role, user_id, submission_id,
                   temperature=0.2, max_tokens=1024, ctx=None, routing_hint=None)
```

1. `tier = router.decide(agent_role, ctx, routing_hint)`
2. 调用对应客户端
3. 异常 → 回退另一层级，记录 warning
4. `router.add_cost(resp.cost_yuan)` 累加预算

### 3.4 模型客户端

两个客户端共享 `OpenAICompatibleClient` 基类（智谱与 Ollama 均提供 OpenAI 兼容接口）：

| 项 | 云端 | 端侧 |
|---|---|---|
| base_url | `https://open.bigmodel.cn/api/paas/v4` | `http://localhost:11434/v1` |
| model | glm-4.7-flash | qwen2.5:7b |
| 并发闸 | Semaphore(1) | Semaphore(2) |
| 单价 | 配置项（当前免费=0） | 0 |

**限流处理**：`RETRYABLE_STATUS = {429, 500, 502, 503, 504}`；收到 429 时设置全局 `_rate_limit_until`，后续请求在过闸前等待该时间点，退避 10s 起、逐次加倍，最多 4 次。

### 3.5 路由决策器

```python
def decide(agent_role, ctx, routing_hint=None) -> str:
    # 1. 强制开关
    # 2. 预算兜底
    # 3. 角色规则表
```

规则表以常量形式集中定义，便于论文中直接引用（见《概要设计》3.3 节）。

### 3.6 知识服务

| 函数 | 职责 |
|---|---|
| `get_concepts(language)` | 该语言概念全集，5 分钟缓存；DB 不可用时回退内置词表 |
| `on_diagnosis(user_id, problem_id, language, concepts)` | 过滤越界概念 → 标注题目 → 掌握度衰减 |
| `record_outcome(user_id, problem_id, language)` | AC 后强化该题 Top5 标注概念 |
| `get_weak_concepts(user_id, language, limit)` | 掌握度 < 0.6 的概念，升序 |

**外键保护**：LLM 可能输出词表外概念，写入前用 `_known_concepts` 过滤，避免外键报错与脏数据。

## 4. 前端详细设计

### 4.1 页面与路由

| 路径 | 组件 | 鉴权 |
|---|---|---|
| `/login` | LoginView | 仅未登录（requiresGuest） |
| `/register` | RegisterView | 无限制（允许已登录打开） |
| `/problems` | ProblemListView | 需登录 |
| `/problems/:id` | ProblemView | 需登录 |
| `/submissions/:id` | SubmissionView | 需登录 |
| `/dashboard` | DashboardView | 需登录 |

**路由守卫**：`requiresAuth` 未登录→`/login`；`requiresGuest` 已登录→`/problems`。

> 注意：`/register` 若加 `requiresGuest`，已登录用户会被静默弹回，表现为"页面不存在"。该问题在实现中出现过，最终移除了该标记。

### 4.2 关键组件

**CodeEditor.vue** —— Monaco 封装：
- `language` 变化时调用 `monaco.editor.setModelLanguage`
- `alwaysConsumeMouseWheel: false`，避免滚轮被困在编辑器内
- 容器 `height: 100%`，外层固定高度

**DiagnosisPanel.vue** —— 四 Tab 共享面板：
- props：`diagnosis`、`loading`
- 辅导策略标签色、审查问题严重度标签色
- 加载提示明确告知"免费模型限流下约需 1-3 分钟"

**AppTopbar.vue** —— 全局导航：品牌（回题库）、题库、仪表盘、用户名、退出登录。

### 4.3 多语言支持

`utils/languages.ts` 维护四语言的 `{ value, label, monacoId, template }`。切换语言时替换为对应初始模板，并提示会重置内容。

### 4.4 图表实现

不使用图表库（避免引入 ~1MB 依赖），以 CSS 实现条形图：

- **掌握度**：排名横向条形图，最薄弱在前，`< 0.4` 标红
- **延迟对比**：按 Agent 角色分组的双条（蓝=端侧 `#2a78d6`，橙=云端 `#eb6834`）
- **配色校验**：两色在色觉障碍模拟下 ΔE 24.7（阈值 8），对比度均 ≥3:1
- **第二编码**：每组数据配等价表格视图，颜色不是唯一区分手段

## 5. 关键实现问题与解决（可用于论文"实现与测试"章节）

| 问题 | 现象 | 根因 | 解决 |
|---|---|---|---|
| 并发调用失败 | 4 个 Agent 仅 1 个返回 | 免费模型并发配额低，并行请求 429 | 云端客户端 Semaphore(1) 串行化 |
| 全部降级 | 4 个 Agent 均失败 | 限流为分钟级窗口，短退避全在窗口内空转 | 429 全局冷却时间戳 + 加倍退避 |
| 结果丢失 | "诊断失败"但日志显示调用成功 | 全流程 2min20s > Go/axios 120s 超时 | 两端超时统一放宽至 300s |
| 规划空白 | 规划 Tab 无内容 | 输出恰好 1024 tokens 被截断，JSON 不完整 | 按 Agent 配置 max_tokens，规划 1536 |
| 概念错配 | Python 提交命中"切片""goroutine" | 知识图谱仅 Go 词表 | 迁移 006/007 语言分区 + 提示词注入语言词表 |
| 同名概念丢失 | Java 19 概念只入库 8 个 | `knowledge_nodes` 主键为 `name` 单列 | 迁移 007 改为复合主键 (language, name) |
| 编辑器无法滚动 | 上下显示不全 | Vite 模板残留 `#app{width:1126px}` + Monaco 吞噬滚轮 | 清理全局样式 + `alwaysConsumeMouseWheel:false` |
| 注册页打不开 | 访问 `/register` 跳回题库 | 路由守卫 `requiresGuest` 对已登录用户生效 | 移除该 meta |
| 端侧 gcc 镜像不存在 | 拉取 `gcc:13-alpine` 403 | 官方 GCC 无 alpine 变体 | 改用 `gcc:12` |
